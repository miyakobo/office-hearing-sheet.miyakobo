# オフィス要件ヒアリングシート（宮工房）

オフィス移転・改装案件のヒアリングをWeb上で行うためのツールです。

- `index.html` … お客様（社外・社内どちらも）が入力する6ステップ＋確認画面のヒアリングフォーム
- `admin.html` … 石川さん・社内スタッフ専用の回答一覧（パスワード保護）
- `gas/` … 送信データの保存・メール通知を行うバックエンド（Google Apps Script）

## 全体の仕組み

```
企業担当者・社内スタッフ（全員共通の1つのURL）
   │  https://<サイトURL>/index.html
   ▼
index.html（静的サイト）── 送信 ──▶ Google Apps Script Web App
                                        │─ スプレッドシートに1行追記
                                        └─ ishikawa@miyakobo.com へメール送信（写真・資料も添付）

石川さん・社内スタッフ
   │  https://<サイトURL>/admin.html
   ▼
admin.html（パスワード保護）── 一覧取得 ──▶ 同じ Apps Script Web App（管理者パスワード必須）
```

**なぜこの構成か**: フォームのURLは誰に渡しても同じ1つですが、回答が集まるスプレッドシート自体を外部と共有していないため、他社の回答を見る手段はそもそもありません。回答を読み返す・一覧化するエンドポイントは管理者パスワードでしか呼び出せず、フォーム送信側のページにはそもそも回答データへアクセスする手段がありません。また、メール送信はこのApps Scriptを設置したGoogleアカウント（miyakobo.com）から行われるため、**誰が入力・送信しても必ず ishikawa@miyakobo.com に届きます**。

## 必須項目（入力者情報）

フォームの一番最初、**「00 入力者情報」**というステップで、以下の4項目を**必須**でご入力いただきます。未入力のままでは次のステップに進めず、送信もできません（画面上・Apps Script側の両方でチェックしています）。

- **会社名**
- **お名前**
- **メールアドレス**
- **電話番号**

ここで入力する「会社名・お名前」は、**フォームに実際に記入している人**の情報です（お客様本人・協力業者様・宮工房の社内スタッフのいずれか）。次の「01 プロジェクト概要」で入力する「会社名・ご担当者名」は、**移転・改装案件そのものの会社名・担当者**です。協力業者様がお客様の代わりに記入する場合など、この2つが異なることがあります。

## セットアップ手順

### 1. スプレッドシートとApps Scriptの準備

1. Googleドライブ（miyakobo.comのアカウント）で新しいスプレッドシートを作成する（例: 「オフィス要件ヒアリング_回答」）。
2. メニュー「拡張機能」→「Apps Script」を開く。
3. デフォルトの `Code.gs` の中身を、このリポジトリの `gas/Code.gs` の内容で置き換える。
4. 左メニューの「プロジェクトの設定」→「`appsscript.json`マニフェストファイルをエディタで表示する」を有効にし、このリポジトリの `gas/appsscript.json` の内容で置き換える。
5. 保存する。

### 2. 管理者パスワードの設定

1. 手順1のスプレッドシートに戻り、ページを再読み込みする（メニューに「宮工房ヒアリングツール」が追加されます／初回はメニュー表示に1分ほどかかることがあります）。
2. 「宮工房ヒアリングツール」→「管理者パスワードを設定…」から、`admin.html` に入力するパスワードを決めて設定する。

### 3. ウェブアプリとしてデプロイ

1. Apps Scriptエディタ右上「デプロイ」→「新しいデプロイ」。
2. 種類の選択で「ウェブアプリ」を選ぶ。
3. 「次のユーザーとして実行」= **自分**、「アクセスできるユーザー」= **全員** を選択してデプロイ。
4. 初回は権限の承認画面が出るので、miyakobo.comのアカウントで承認する（Gmail送信・スプレッドシートへのアクセス許可のみ。Googleドライブへのアクセスは一切求めません）。
5. 発行された **ウェブアプリのURL**（`https://script.google.com/macros/s/xxxxx/exec`）を控える。

> コードを更新した場合は「デプロイ」→「デプロイを管理」→ 対象の鉛筆アイコンから「新しいバージョン」を選んで再デプロイしてください（URLは変わりません）。
>
> **メールアドレス・電話番号欄、確認メール、シートの見やすさ改善（2024年追加分）を反映する場合**: `gas/Code.gs` を最新の内容に貼り替えて「新しいバージョン」として再デプロイするだけで反映されます。`gas/appsscript.json`（権限設定）は変更していないため、**再承認は不要**です。ただし、既に運用中の`Submissions`シートは見出しが1段のままなので、シート名を`Submissions_old`などにリネームしてから再度フォームを送信すると、新しい2段見出しのシートが自動で作り直されます（過去データは`Submissions_old`にそのまま残ります）。
>
> **会社名・メールアドレス・お電話番号を必須項目にした際も同様**です。`gas/Code.gs`を貼り替えて再デプロイするだけで、権限の再承認は不要です（シートの列構成は変わっていないため、シートの作り直しも不要です）。
>
> **一番左に「案件名」列を追加し、セクションごとの色分け・境界線を見やすくした際も同様**です。`gas/Code.gs`を貼り替えて再デプロイすれば反映されます。ただし列の並びが変わっているため、既にデータが入っているシートでは列がズレて見えます。シート名を`Submissions_old3`などにリネームしてから1件テスト送信すると、新しいレイアウトのシートが自動で作り直されます（過去データは`Submissions_old3`にそのまま残ります）。
>
> **フォームを「00 入力者情報」の新設・6ステップ構成に全面刷新した際も同様**です。`gas/Code.gs`・`index.html`・`admin.html`を最新の内容に貼り替えて再デプロイ・再公開すれば反映されます。権限の再承認は不要です。この変更で「案件名」の項目自体がフォームから無くなり、代わりに「会社名（案件）」列がシートの一番左（識別列の先頭）に来ています。また列構成が大きく変わったため、シート名を`Submissions_old4`などにリネームしてから1件テスト送信し、シートを新しいレイアウトで作り直してください。
>
> **企業別リンク（トークン）の仕組みを廃止した際も同様**です。以前は取引先ごとに`?c=<トークン>`付きの専用URLを発行していましたが、そもそもスプレッドシート自体を外部と共有していないため、URLを分けなくても他社に回答が見られる心配はありませんでした。運用の手間だけがかかっていたため撤去し、**フォームのURLは1つ（`?c=`なし）を誰にでも渡すだけ**に変更しています。`gas/Code.gs`・`index.html`・`admin.html`を最新の内容に貼り替えて再デプロイ・再公開してください。権限の再承認は不要です。「送信元区分」「リンクトークン」「登録会社名（トークン）」の3列がシートから無くなり、その分列構成が変わるため、シート名を`Submissions_old5`などにリネームしてから1件テスト送信し、シートを新しいレイアウトで作り直してください（`Companies`シートは以後使いません。残っていても実害はないので、削除してもそのまま残しても構いません）。
>
> **「会社名（案件）」列・「ひとことまとめ」列を削除し、「送信日時」列の表示形式を変えた際も同様**です。要件サマリー（全文）を見れば内容がわかるため、この2列は廃止しました（「会社名（案件）」欄に入力された内容自体は、引き続き「要件サマリー（全文）」の中に含まれています）。あわせて「送信日時」列は「9月15日 11:49」のように月日・時分だけの見やすい表示に変更しています（セルの中身自体は日時のままなので、並べ替えは今までどおり正しく機能します）。`gas/Code.gs`・`admin.html`を最新の内容に貼り替えて再デプロイ・再公開してください。権限の再承認は不要です。列構成が変わるため、シート名を`Submissions_old6`などにリネームしてから1件テスト送信し、シートを新しいレイアウトで作り直してください。
>
> **「03 求める空間イメージ」の「言葉でのご指定（その他）」欄を削除した際も同様**です。写真タイルからの選択で十分と判断し撤去しました。`gas/Code.gs`を貼り替えて再デプロイすれば反映されます。権限の再承認は不要です。「空間イメージ（その他）」列がシートから無くなるため、シート名を`Submissions_old7`などにリネームしてから1件テスト送信し、シートを新しいレイアウトで作り直してください。

### 4. フロントエンドにURLを設定

- `index.html` 内の `var GAS_WEBAPP_URL = "";` に、手順3で控えたURLを設定する。
- `admin.html` 内の `var GAS_WEBAPP_URL = "";` にも同じURLを設定する。

### 5. サイトの公開（GitHub Pages）

1. GitHubリポジトリの Settings → Pages で、このブランチ（またはmainにマージ後）を公開元に設定する。
2. 公開後のURL:
   - フォーム: `https://miyakobo.github.io/office-hearing-sheet.miyakobo/index.html`
   - 管理画面: `https://miyakobo.github.io/office-hearing-sheet.miyakobo/admin.html`

他の静的ホスティング（Netlify・Vercel・Cloudflare Pagesなど）でも、`index.html` と `admin.html` をそのまま配置すれば動きます。

> このリポジトリは個人アカウント`raraji827`から、Organization `miyakobo` に移動済みです。これにより、サイトURLの先頭が `raraji827.github.io` から `miyakobo.github.io` に変わりました。フォームのURLは1つだけなので、案内し直す先は`admin.html`・`index.html`のリンクを渡してある相手全員です。

### 6.（あとで・任意）独自ドメインの設定

サイトのURLの先頭を `hearing.miyakobo.com` のような独自ドメインに切り替えることもできます。ただしDNSの設定
（ドメイン管理画面での操作）が必要になるため、**今は保留**にしています。必要になったらいつでも対応するので、
その時に声をかけてください。

## フォームの配布方法

企業向け・社内向けの区別なく、**同じ1つのURLをそのまま渡すだけ**です。

```
https://<サイトURL>/index.html
```

- 誰が開いても同じフォームです。回答者が「00 入力者情報」で会社名・お名前・メールアドレス・電話番号を入力するので、それが誰からの回答かの識別情報になります。
- URLを企業ごとに使い分ける必要はありません（以前あったトークン発行の仕組みは廃止しました）。

## 回答の確認方法

- **スプレッドシート**: `Submissions`シートに1送信＝1行で自動記録されます。見出しは2段になっており、1段目が「00 入力者情報」〜「05 特記事項・物件資料」のセクション名、2段目が各設問名です。セクションごとに背景色を交互に変え、境目に太い縦線を入れているので、どこからどこまでが同じ設問グループか一目でわかります。一番左は**「送信日時・社内担当者・対応状況」**の3列が固定表示され、右にスクロールしても常に見えます。
  - **送信日時**は「9月15日 11:49」のように月日・時分だけを表示しています。
  - **社内担当者**・**対応状況**（未対応／対応中／完了）は、フォームからは送られてこない手入力欄です。案件を割り振ったら、この2列にシート上で直接書き込んでください（対応状況はプルダウンから選べます）。
  - 各回答の内容は、一番右の**「要件サマリー（全文）」**列にまとまっているので、まずはそこを読めば全体像がわかります。
- **admin.html**: ブラウザで開き、手順2で設定した管理者パスワードでログインすると、一覧（対応状況・社内担当者付き）と詳細パネルが確認できます。ただし社内担当者・対応状況の変更はスプレッドシート側で行ってください（admin.htmlは閲覧専用です）。

## 送信者への自動返信

フォーム送信時、00「入力者情報」の「メールアドレス」欄（必須項目）宛に、記入者本人にも
「担当者に届きました。折り返しをお待ちください」という内容の確認メールが自動送信されます
（送信元はApps Scriptを設置したGoogleアカウント）。メールアドレスが必須項目になったため、
通常は送信のたびに必ず届きます。万一メール送信に失敗した場合でも、スプレッドシートへの記録・
石川さんへの通知メールは通常どおり行われます。

## 運用上の注意

- **写真・資料の保存先**: Google Driveには一切保存せず、送信時にメールへ直接添付するだけの、最もシンプルな構成にしています（Driveの権限が不要なため、設定・トラブルが起きにくい）。スプレッドシートとadmin.htmlには添付ファイルの「ファイル名」だけが記録され、実物は届いたメールの添付ファイルから確認してください。
- **Gmail添付の上限**: Gmailは1通あたり添付合計25MBが上限です。フォーム側は写真1枚8MB・最大5枚、資料1件10MB・最大5件に制限していますが、大きなファイルが複数添付されると失敗する可能性があります。
- **管理者パスワードの運用**: `admin.html`のパスワードは平文でApps Script側と比較しているだけの簡易な保護です。より強固にしたい場合は、Google Workspaceのログイン（`Session.getActiveUser()`のドメイン確認）に切り替えることも可能です。ご希望があれば追加実装します。
- **新しいヒアリング項目の追加**: `index.html` の `SECTIONS` 配列を編集するだけで、設問の追加・変更・削除ができます（コード全体を触る必要はありません）。各セクションに `detail:{...}` を追加すると、「＋ 詳しく入力する（任意）」ボタンで開閉できる追加設問のブロックになります（必須ではない、より詳しく聞きたい項目向け）。

## ローカルでの動作確認

```bash
python3 -m http.server 8000
# ブラウザで http://localhost:8000/index.html を開く
```

`GAS_WEBAPP_URL` が未設定の間は、送信ボタンを押すと「送信先が未設定です」という案内が出ます（デプロイ前でも画面の見た目・入力・自動保存・サマリー生成の確認は可能です）。
