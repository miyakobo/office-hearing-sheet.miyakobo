# オフィス要件ヒアリングシート（宮工房）

オフィス移転・改装案件のヒアリングをWeb上で行うためのツールです。

- `index.html` … お客様（社外・社内どちらも）が入力する9ステップのヒアリングフォーム
- `admin.html` … 石川さん・社内スタッフ専用の回答一覧（パスワード保護）
- `gas/` … 送信データの保存・メール通知を行うバックエンド（Google Apps Script）

## 全体の仕組み

```
企業担当者・社内スタッフ
   │  https://<サイトURL>/index.html?c=<会社ごとのトークン>
   ▼
index.html（静的サイト）── 送信 ──▶ Google Apps Script Web App
                                        │─ スプレッドシートに1行追記
                                        └─ ishikawa@miyakobo.com へメール送信（写真・資料も添付）

石川さん・社内スタッフ
   │  https://<サイトURL>/admin.html
   ▼
admin.html（パスワード保護）── 一覧取得 ──▶ 同じ Apps Script Web App（管理者パスワード必須）
```

**なぜこの構成か**: 複数の取引先（A社・B社…）に配布しても、企業ごとの提出内容はお互いに一切見えません。回答を読み返す・一覧化するエンドポイントは管理者パスワードでしか呼び出せず、フォーム送信側のページにはそもそも他社データへアクセスする手段がありません。また、メール送信はこのApps Scriptを設置したGoogleアカウント（miyakobo.com）から行われるため、**誰が入力・送信しても必ず ishikawa@miyakobo.com に届きます**。

## 必須項目（依頼主情報）

フォームの一番最初（01 プロジェクト概要の先頭）で、以下の4項目を**必須**でご入力いただきます。未入力のままでは次のステップに進めず、送信もできません（画面上・Apps Script側の両方でチェックしています）。

- **ご依頼主区分**：「お客様」「協力業者様」「社内」のいずれかを選択
- **会社名**
- **メールアドレス**
- **お電話番号**

これにより、誰が（どんな立場の人が）送ってきたのかが、スプレッドシートの「ご依頼主区分」列でひと目でわかります。なお、トークンリンク（`?c=`）による会社の自動判定（「送信元区分」列）とは別の情報です。「送信元区分」はリンクをもとにサーバー側で機械的に判定される情報（なりすまし不可）、「ご依頼主区分」は本人が選んだ立場（お客様／協力業者様／社内）です。

## セットアップ手順

### 1. スプレッドシートとApps Scriptの準備

1. Googleドライブ（miyakobo.comのアカウント）で新しいスプレッドシートを作成する（例: 「オフィス要件ヒアリング_回答」）。
2. メニュー「拡張機能」→「Apps Script」を開く。
3. デフォルトの `Code.gs` の中身を、このリポジトリの `gas/Code.gs` の内容で置き換える。
4. 左メニューの「プロジェクトの設定」→「`appsscript.json`マニフェストファイルをエディタで表示する」を有効にし、このリポジトリの `gas/appsscript.json` の内容で置き換える。
5. 保存する。

### 2. 管理者パスワードの設定

1. 手順1のスプレッドシートに戻り、ページを再読み込みする（メニューに「宮工房ヒアリングツール」が追加されます／初回はメニュー表示に1分ほどかかることがあります）。
2. 「宮工房ヒアリングツール」→「管理者パスワードを設定…」から、`admin.html` に入力するパスワードを決めて設定する。

### 3. ウェブアプリとしてデプロイ

1. Apps Scriptエディタ右上「デプロイ」→「新しいデプロイ」。
2. 種類の選択で「ウェブアプリ」を選ぶ。
3. 「次のユーザーとして実行」= **自分**、「アクセスできるユーザー」= **全員** を選択してデプロイ。
4. 初回は権限の承認画面が出るので、miyakobo.comのアカウントで承認する（Gmail送信・スプレッドシートへのアクセス許可のみ。Googleドライブへのアクセスは一切求めません）。
5. 発行された **ウェブアプリのURL**（`https://script.google.com/macros/s/xxxxx/exec`）を控える。

> コードを更新した場合は「デプロイ」→「デプロイを管理」→ 対象の鉛筆アイコンから「新しいバージョン」を選んで再デプロイしてください（URLは変わりません）。
>
> **メールアドレス・電話番号欄、確認メール、シートの見やすさ改善（2024年追加分）を反映する場合**: `gas/Code.gs` を最新の内容に貼り替えて「新しいバージョン」として再デプロイするだけで反映されます。`gas/appsscript.json`（権限設定）は変更していないため、**再承認は不要**です。ただし、既に運用中の`Submissions`シートは見出しが1段のままなので、シート名を`Submissions_old`などにリネームしてから再度フォームを送信すると、新しい2段見出しのシートが自動で作り直されます（過去データは`Submissions_old`にそのまま残ります）。
>
> **「ご依頼主区分」必須項目を追加した際も同様**です。`gas/Code.gs`を貼り替えて再デプロイするだけで、権限の再承認は不要です。既に上記の2段見出しシートに切り替え済みの場合は、列が1つ増えるため、もう一度シート名を`Submissions_old2`などにリネームしてから1件テスト送信し、シートを作り直してください。

### 4. フロントエンドにURLを設定

- `index.html` 内の `var GAS_WEBAPP_URL = "";` に、手順3で控えたURLを設定する。
- `admin.html` 内の `var GAS_WEBAPP_URL = "";` にも同じURLを設定する。

### 5. サイトの公開（GitHub Pages）

1. GitHubリポジトリの Settings → Pages で、このブランチ（またはmainにマージ後）を公開元に設定する。
2. 公開後のURL例: `https://<ユーザー名>.github.io/<リポジトリ名>/index.html`

他の静的ホスティング（Netlify・Vercel・Cloudflare Pagesなど）でも、`index.html` と `admin.html` をそのまま配置すれば動きます。

### 6.（あとで・任意）独自ドメインの設定

サイトのURLの先頭に `raraji827.github.io` と出るのが気になる場合、`hearing.miyakobo.com` のような
独自ドメインに切り替えることもできます。ただしDNSの設定（ドメイン管理画面での操作）が必要になるため、
**今は保留**にしています。必要になったらいつでも対応するので、その時に声をかけてください。

## 企業ごとの専用リンクの発行

1. 手順1のスプレッドシートを開き、「宮工房ヒアリングツール」→「新しい企業リンクを発行…」から会社名を入力する。
2. `xxxxxxxxxx` のようなランダムなトークンが発行され、`Companies` シートに記録される。
3. 発行されたトークンを使い、下記のURLをその会社にだけ送付する。

```
https://<サイトURL>/index.html?c=<トークン>
```

- トークンが付いていない状態（`?c=`なし）で開いた場合は「社内利用モード」として扱われ、回答一覧では区分「社内」として記録されます。
- トークンは会社名そのものではなくランダム文字列なので、URLを見ただけでは他社に会社名が推測されません。

## 回答の確認方法

- **スプレッドシート**: `Submissions`シートに1送信＝1行で自動記録されます。見出しは2段になっており、1段目が「01 プロジェクト概要」〜「08 特記事項・物件資料」のセクション名、2段目が各設問名です。左端の「送信日時・送信元区分・社内担当者・対応状況・ひとことまとめ」の5列は固定表示され、右にスクロールしても常に見えます。
  - **社内担当者**・**対応状況**（未対応／対応中／完了）は、フォームからは送られてこない手入力欄です。案件を割り振ったら、この2列にシート上で直接書き込んでください（対応状況はプルダウンから選べます）。
  - **ひとことまとめ**は、会社名・案件種別・時期や予算・人数・優先要件などから自動で作られる1〜2文の要約です。列がたくさんあっても、この列だけ読めばだいたいの内容がわかります。
- **admin.html**: ブラウザで開き、手順2で設定した管理者パスワードでログインすると、一覧（対応状況・社内担当者・ひとことまとめ付き）と詳細パネルが確認できます。ただし社内担当者・対応状況の変更はスプレッドシート側で行ってください（admin.htmlは閲覧専用です）。

## 送信者への自動返信

フォーム送信時、01の「ご担当者のメールアドレス」欄に記入があった場合は、記入者本人にも
「担当者に届きました。折り返しをお待ちください」という内容の確認メールが自動送信されます
（宛先はフォームに記入されたアドレス、送信元はApps Scriptを設置したGoogleアカウント）。
メールアドレス未記入の場合や送信に失敗した場合でも、スプレッドシートへの記録・石川さんへの
通知メールは通常どおり行われます。

## 運用上の注意

- **写真・資料の保存先**: Google Driveには一切保存せず、送信時にメールへ直接添付するだけの、最もシンプルな構成にしています（Driveの権限が不要なため、設定・トラブルが起きにくい）。スプレッドシートとadmin.htmlには添付ファイルの「ファイル名」だけが記録され、実物は届いたメールの添付ファイルから確認してください。
- **Gmail添付の上限**: Gmailは1通あたり添付合計25MBが上限です。フォーム側は写真1枚8MB・最大5枚、資料1件10MB・最大5件に制限していますが、大きなファイルが複数添付されると失敗する可能性があります。
- **管理者パスワードの運用**: `admin.html`のパスワードは平文でApps Script側と比較しているだけの簡易な保護です。より強固にしたい場合は、Google Workspaceのログイン（`Session.getActiveUser()`のドメイン確認）に切り替えることも可能です。ご希望があれば追加実装します。
- **新しいヒアリング項目の追加**: `index.html` の `SECTIONS` 配列を編集するだけで、設問の追加・変更・削除ができます（コード全体を触る必要はありません）。

## ローカルでの動作確認

```bash
python3 -m http.server 8000
# ブラウザで http://localhost:8000/index.html を開く
```

`GAS_WEBAPP_URL` が未設定の間は、送信ボタンを押すと「送信先が未設定です」という案内が出ます（デプロイ前でも画面の見た目・入力・自動保存・サマリー生成の確認は可能です）。
